# @usertrack/better-auth

Official [UserTrack](https://usertrack.dev) plugin for [Better Auth](https://www.better-auth.com).

## What it does

- Tracks your **registered-user growth** in UserTrack (total users, new users in 24h / 7d / 30d, daily history) straight from your Better Auth database — verified, read-only, synced every 4 hours.
- **Never exposes user PII.** UserTrack receives aggregate counts and timestamps only. No emails, names, password hashes, session or verification tokens, no per-user records.
- Supports **verified pull**: UserTrack calls a signed endpoint that the plugin adds to your Better Auth instance (`POST <basePath>/usertrack/metrics`) and checks the response signature.
- Optionally pushes **lifecycle events** (`user.created`, `user.deleted`) so your UserTrack dashboard shows signups between syncs. Delivery is fire-and-forget: it never blocks and never fails a signup.

Better Auth powers the **Signed up** stage of your UserTrack funnel. Activation (PostHog, a table, custom SQL) and conversion (Stripe, RevenueCat, …) are connected separately in UserTrack — or report them from the same app with [`@usertrack/node`](https://www.npmjs.com/package/@usertrack/node): `createUserTrackHandler({ users: betterAuthUsers(adapter, { excludeAnonymous }), activation, conversion })` reuses this plugin's user counter.

## Installation

```bash
npm install @usertrack/better-auth
# pnpm add @usertrack/better-auth · yarn add @usertrack/better-auth · bun add @usertrack/better-auth
```

Peer dependency: `better-auth >= 1.3`. Depends on `@usertrack/protocol` and `@usertrack/node` (zero further dependencies). ESM only, Node 18.17+ (also runs on edge runtimes with WebCrypto).

## Quickstart

```ts
import { betterAuth } from "better-auth";
import { userTrack } from "@usertrack/better-auth";

export const auth = betterAuth({
  // ...your existing configuration stays unchanged
  plugins: [
    // ...your existing plugins stay unchanged
    userTrack({
      projectId: process.env.USERTRACK_PROJECT_ID!,
      secret: process.env.USERTRACK_SECRET!,
    }),
  ],
});
```

Deploy, then click **Verify** in UserTrack (or let your agent call `usertrack_verify_integration`). Done.

## Environment variables

```env
USERTRACK_PROJECT_ID=   # your UserTrack project id
USERTRACK_SECRET=       # ut_int_… — generated by UserTrack, shown once
```

Both are created for you in the UserTrack dashboard (project → Integrations → Users → Better Auth) or by the MCP tool `usertrack_create_integration`. The secret is only displayed at creation; if you lose it, rotate it — the old one stops working immediately.

## Options

```ts
userTrack({
  projectId: string;   // required
  secret: string;      // required
  endpoint?: string;   // default "https://usertrack.dev" — only for self-hosted UserTrack
  events?: boolean;    // default true — push user.created / user.deleted events
  debug?: boolean;     // default false — log delivery problems through the Better Auth logger
})
```

## UserTrack setup

1. Create a UserTrack account and a project for your product.
2. Under **Integrations → Users** pick **Better Auth** and enter your Better Auth base URL (e.g. `https://app.example.com/api/auth`).
3. Copy `USERTRACK_PROJECT_ID` and `USERTRACK_SECRET` into your app's environment.
4. Install the package and add the plugin (above), deploy.
5. Click **Verify**. UserTrack reads your total user count, records the first verified snapshot and syncs every 4 hours from then on.

## Security

- **Read-only, aggregate metrics.** The plugin exposes counts, never user data.
- **Both directions are signed** with HMAC-SHA256 using the integration secret: UserTrack signs each metrics request (method, path, timestamp, nonce, body hash); the plugin verifies it with a timing-safe comparison, rejects timestamps outside a 5-minute window, refuses replayed nonces, and signs the response bound to the request nonce. Events pushed to UserTrack carry the same signature.
- **No PII.** Events contain an HMAC-derived pseudonymous subject, not the user id.
- **The secret stays in your environment.** Never hardcode or commit it. Rotate it from UserTrack at any time.
- **Rate limited**: the metrics endpoint allows 30 requests per minute (Better Auth rate limiter).

## How verification works

**Pull (source of truth).** Every 4 hours UserTrack sends `POST <basePath>/usertrack/metrics` with `{ "protocolVersion": 1 }` (plus `days` for the 30-day history on first sync, or `from` / `to` for an arbitrary window). The plugin counts users with `createdAt` filters through your Better Auth database adapter (`adapter.count`, with a bounded id-only scan as fallback) and answers:

```json
{
  "protocolVersion": 1,
  "clientVersion": "0.2.0",
  "source": "better-auth",
  "projectId": "…",
  "generatedAt": "2026-09-03T08:00:00.000Z",
  "users": { "totalUsers": 12481, "newUsers": { "24h": 84, "7d": 491, "30d": 1832 }, "daily": [{ "day": "2026-08-04", "newUsers": 51 }] },
  "capabilities": { "exactCounts": true, "history": true, "anonymousExcluded": false, "roles": ["users"] }
}
```

Users created by the Better Auth `anonymous` plugin are excluded automatically when that plugin is installed.

**Push (freshness).** On `user.created` / `user.deleted` the plugin sends a signed event to `https://usertrack.dev/api/integrations/native/events` with a 3-second timeout, after the database write, without awaiting the result in the auth flow. If UserTrack is unreachable the event is dropped and the next pull corrects the numbers.

## MCP setup

Founders using Claude Code, Cursor, Codex or any MCP client can let their coding agent do all of this. Add the UserTrack MCP server (`https://usertrack.dev/mcp`, token from the UserTrack developer page) and say:

> Add this Better Auth project to UserTrack.

The agent detects Better Auth, creates the project and the integration (`usertrack_create_integration`), gets a structured install plan (`usertrack_get_better_auth_setup`: install command for your package manager, code change, env vars, safety rules), edits the config, verifies (`usertrack_verify_integration`) and returns your public UserTrack URL. Docs: https://usertrack.dev/developers#mcp

## Troubleshooting

| Symptom (in UserTrack) | Cause | Fix |
|---|---|---|
| `No UserTrack plugin found at … /usertrack/metrics` (404) | Plugin not installed, not in `plugins`, or the deploy is not live | Install, register `userTrack()`, redeploy |
| `rejected the signature` (401) | `USERTRACK_SECRET` / `USERTRACK_PROJECT_ID` differ from the integration | Fix the env vars (all environments), redeploy, or rotate the secret in UserTrack |
| `rejected the request as stale` | Server clock off by > 5 minutes | Fix NTP on the host |
| `Could not reach …` | Base URL wrong, app down, firewall | Check the URL in UserTrack: it must be `baseURL + basePath` (usually `/api/auth`) |
| `could not count users` (500) | The database adapter failed | Check your adapter logs; `adapter.count` must work on the `user` model |
| `outdated` / `Unsupported plugin protocol version` | Old plugin | `npm update @usertrack/better-auth` |
| Signups look lower than expected | Anonymous users excluded | Expected: only registered users count |

Enable `debug: true` to see event delivery problems in your Better Auth logs. Nothing about UserTrack is ever thrown into your auth flow.

## Publishing / development

```bash
pnpm install                # from the repository root
cd packages/better-auth
pnpm test                   # vitest: metrics, events, endpoint, hooks (memory adapter)
pnpm typecheck
pnpm build                  # tsc → dist/ (ESM + d.ts)
pnpm pack --pack-destination /tmp && tar -tzf /tmp/usertrack-better-auth-*.tgz
```

Releases are tag-driven (`better-auth-v<version>`, see `.github/workflows/release-packages.yml`). Bump `version` in `package.json` and `src/version.ts` together (a test enforces it) and add a `CHANGELOG.md` entry. The wire protocol lives in `@usertrack/protocol` and is frozen by fixtures in `packages/protocol/tests/fixtures/signatures.json`, shared with the UserTrack server tests. Build the workspace first (`pnpm -r --filter "./packages/**" build`) so the workspace dependencies resolve.
