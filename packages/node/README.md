# @usertrack/node

[UserTrack](https://usertrack.dev) SDK for Node and edge runtimes. Mount one signed, read-only handler in your app and UserTrack pulls **aggregate** user-growth metrics from it every 4 hours — verified, without emails, names or any user record leaving your app. Optional adapters for **Prisma**, **Drizzle**, **Convex** and **Auth.js / NextAuth**; a `count()` function is all a custom app needs.

- **Signed up** (required): total users, new users 24h / 7d / 30d, daily history.
- **Activated** (optional): users who reached the first meaningful value in your product.
- **Trial / Converted** (optional): conversion state only — UserTrack never asks for amounts, prices or MRR.
- **Lifecycle events** (optional): `track("user.created", { id })` after your own write, fire-and-forget, never blocks a signup.

Works as a Next.js route export, in Hono, Remix, Bun, Cloudflare Workers, and via `toNodeHandler()` in Express or plain `node:http`. ESM, Node 18.17+, WebCrypto only, zero runtime dependencies (`@usertrack/protocol`).

## Install

```bash
npm install @usertrack/node
# pnpm add @usertrack/node · yarn add @usertrack/node · bun add @usertrack/node
```

## Quickstart (Next.js + Prisma)

```ts
// app/api/usertrack/metrics/route.ts
import { createUserTrackHandler } from "@usertrack/node";
import { prismaUsers } from "@usertrack/node/prisma";
import { prisma } from "@/lib/prisma";

export const POST = createUserTrackHandler({
  projectId: process.env.USERTRACK_PROJECT_ID!,
  secret: process.env.USERTRACK_SECRET!,
  source: "prisma",
  users: prismaUsers(prisma.user),
});
```

Deploy, then click **Verify** in UserTrack (project → Integrations → Users → *My app (SDK)*). UserTrack calls `POST https://your-app.com/api/usertrack/metrics` once, checks the signature, records the first verified snapshot and syncs every 4 hours from then on.

```env
USERTRACK_PROJECT_ID=   # your UserTrack project id
USERTRACK_SECRET=       # ut_int_… — generated by UserTrack, shown once
```

## Handler options

```ts
createUserTrackHandler({
  projectId: string;                    // required
  secret: string;                       // required (ut_int_…)
  users: CountSource;                   // required — registered users
  activation?: CountSource;             // users who reached first value
  conversion?: { converted: CountSource; trial?: CountSource; mode?: "active_paid" | "ever_paid" | "first_payment" };
  identities?: () => Promise<{ signedUp?, activated?, trial?, converted?: { id: string; at?: Date | string }[] }>; // stable ids, never emails
  source?: "prisma" | "drizzle" | "convex" | "authjs" | "custom";  // shown in the dashboard, default "custom"
  debug?: boolean | ((message, meta) => void);
})
```

A **count source** is anything with `count(where)`:

```ts
type CountWhere = { createdAtGte?: Date; createdAtLt?: Date };      // createdAtLt is exclusive
type CountSource = { count(where: CountWhere): Promise<number | { count: number; exact: boolean }>; timeFilter?: boolean };
```

Return `{ count, exact: false }` if you hit a scan cap (UserTrack labels the numbers as approximate). Set `timeFilter: false` if the table has no timestamp — UserTrack then reads totals only and derives windows from its own snapshots.

**The time bounds are what draws your growth curve.** On the first sync UserTrack asks the users source once per day over the last 90 days, so the chart is reconstructed from real signup dates — a user who signed up on 1 September appears on 1 September, not on the day you installed the SDK. Honour `createdAtGte` / `createdAtLt` and the history comes for free; ignore them (or set `timeFilter: false`) and UserTrack stores totals only, with the curve starting the day you connected.

## Adapters

### Prisma — `@usertrack/node/prisma`

```ts
import { prismaUsers, userTrackPrismaExtension } from "@usertrack/node/prisma";

users: prismaUsers(prisma.user)                                      // count({ where: { createdAt: { gte, lt } } })
users: prismaUsers(prisma.user, { where: { deletedAt: null } })      // extra filter on every count
activation: prismaUsers(prisma.workspace, { createdAtField: "createdAt" })
conversion: { converted: prismaUsers(prisma.subscription, { where: { status: "active" } }) }

// optional push hook: user.created / user.deleted after the write succeeded
export const prisma = new PrismaClient().$extends(userTrackPrismaExtension({ projectId, secret }));
```

`createMany` is not hooked (Prisma returns no rows). Models without a timestamp: `prismaUsers(prisma.user, { createdAtField: null })` → totals only.

### Drizzle — `@usertrack/node/drizzle`

```ts
import { drizzleUsers } from "@usertrack/node/drizzle";
import { isNull } from "drizzle-orm";

users: drizzleUsers(db, users, { createdAt: users.createdAt, where: isNull(users.deletedAt) })
```

Runs `select count(*) from users where created_at >= $1 and created_at < $2`. Requires `drizzle-orm` (optional peer dependency) — any driver.

### Convex — `@usertrack/node/convex`

```ts
// convex/usertrack.ts
import { v } from "convex/values";
import { internalQuery } from "./_generated/server";
import { countWithCap } from "@usertrack/node/convex";

export const countUsers = internalQuery({
  args: { createdAtGte: v.optional(v.number()), createdAtLt: v.optional(v.number()) },
  handler: (ctx, { createdAtGte = 0, createdAtLt = Number.MAX_SAFE_INTEGER }) =>
    countWithCap(ctx.db.query("users").withIndex("by_creation_time", (q) => q.gte("_creationTime", createdAtGte).lt("_creationTime", createdAtLt))),
});

// convex/http.ts
import { httpRouter } from "convex/server";
import { httpAction } from "./_generated/server";
import { internal } from "./_generated/api";
import { convexHandler } from "@usertrack/node/convex";

const http = httpRouter();
http.route({ path: "/usertrack/metrics", method: "POST", handler: httpAction(convexHandler({ projectId: process.env.USERTRACK_PROJECT_ID!, secret: process.env.USERTRACK_SECRET!, users: internal.usertrack.countUsers })) });
export default http;
```

**Count the table that owns the user record.** An analytics or event-log table — a `growthEvents` table with one `signup_completed` row per user, say — looks like the right source but only holds rows from the day it shipped, so UserTrack reports a brand-new product with a flat history and no backfill can recover the missing rows.

With [`@convex-dev/better-auth`](https://github.com/get-convex/better-auth) your users live in the auth component rather than in your own schema. Page its `user` table — the component has no `createdAt` index, so window in memory:

```ts
// convex/usertrack.ts
import { components } from "./_generated/api";

const CAP = 10_000;

export const countUsers = internalQuery({
  args: { createdAtGte: v.optional(v.number()), createdAtLt: v.optional(v.number()) },
  handler: async (ctx, { createdAtGte = 0, createdAtLt = Number.MAX_SAFE_INTEGER }) => {
    const times: number[] = [];
    let cursor: string | null = null;
    while (times.length <= CAP) {
      const page: { page: { createdAt: number }[]; isDone: boolean; continueCursor: string } = await ctx.runQuery(components.betterAuth.adapter.findMany, {
        model: "user",
        select: ["createdAt"],
        paginationOpts: { cursor, numItems: 1_000 },
      });
      for (const user of page.page) times.push(user.createdAt);
      if (page.isDone) break;
      cursor = page.continueCursor;
    }
    return { count: times.slice(0, CAP).filter((at) => at >= createdAtGte && at < createdAtLt).length, exact: times.length <= CAP };
  },
});
```

Activation and conversion sources are windowed the same way, so they need the timestamp of *that* stage: key activation on each user's first value-event (dedupe by owner, take the earliest) and conversion on when the account started paying. Filtering paid accounts by their signup date means someone who upgrades months later never appears in `newConverted30d`.

Convex has no cheap `count`: `countWithCap` reads up to 10,000 documents (`cap + 1` via `.take`) and reports `exact: false` beyond that, which UserTrack shows as *approximate*. For bigger tables keep an exact counter with [`@convex-dev/aggregate`](https://www.convex.dev/components/aggregate) and return its value instead. The base URL in UserTrack is your Convex site URL, e.g. `https://happy-otter-123.convex.site` (the handler is mounted at `/usertrack/metrics`). Set the env vars with `npx convex env set USERTRACK_PROJECT_ID … && npx convex env set USERTRACK_SECRET …`.

### Auth.js / NextAuth — `@usertrack/node/authjs`

Auth.js adapters expose no count method, so counting goes through the database adapter you already use:

```ts
// auth.ts
import { userTrackAuthjsEvents } from "@usertrack/node/authjs";
export const { handlers, auth } = NextAuth({ adapter: PrismaAdapter(prisma), events: { ...userTrackAuthjsEvents({ projectId, secret }) } });

// app/api/usertrack/metrics/route.ts
export const POST = createUserTrackHandler({ projectId, secret, source: "authjs", users: prismaUsers(prisma.user, { createdAtField: null }) });
```

The default Auth.js `User` model has **no `createdAt`** column: add `createdAt DateTime @default(now())` (Prisma) / `createdAt: timestamp("created_at").defaultNow()` (Drizzle) to unlock 24h / 7d / 30d signups and history; otherwise pass `createdAtField: null` for totals only.

### Custom — anything with a count

```ts
export const POST = createUserTrackHandler({
  projectId, secret,
  users: { count: ({ createdAtGte, createdAtLt }) => db.count("users", { createdAt: { ">=": createdAtGte, "<": createdAtLt } }) },
});
```

## Express / Node http

```ts
import { createUserTrackHandler, toNodeHandler } from "@usertrack/node";
app.post("/api/usertrack/metrics", toNodeHandler(createUserTrackHandler({ … })));
```

Hono: `app.post("/api/usertrack/metrics", (c) => usertrack(c.req.raw))`. Remix / React Router: `export const action = ({ request }) => usertrack(request)`.

## Lifecycle events (optional)

```ts
import { createTracker } from "@usertrack/node";
const usertrack = createTracker({ projectId, secret, source: "custom" });
usertrack.track("user.created", { id: user.id });          // after your insert
usertrack.track("user.activated", { id: user.id });
usertrack.track("trial.started", { id: user.id });
usertrack.track("user.converted", { id: user.id, at: paidAt });
```

`track()` returns immediately and never throws; delivery has a 3 s timeout. The id is HMAC-pseudonymised before it leaves your app. Events only annotate the dashboard between syncs — the pull is always the source of truth. `deliver()` returns the delivery result for tests and job runners.

## Security

- **Read-only, aggregate metrics.** The handler exposes counts, never rows.
- **Both directions are signed** (HMAC-SHA256 over method, path, timestamp, nonce and body hash; ±5 min; nonce replay cache; response bound to the request nonce). See `@usertrack/protocol`.
- **The secret stays in your environment.** Never hardcode or commit it; rotate it in UserTrack at any time.
- **No PII** — identities you choose to report must be your opaque user ids (anything containing `@` is dropped).

## Troubleshooting

| Symptom (in UserTrack) | Cause | Fix |
|---|---|---|
| `No UserTrack handler found at …/metrics` (404) | Route not mounted at the URL you entered, or the deploy is not live | Mount the handler, redeploy, check the base URL (metrics live at `<base>/metrics`) |
| `rejected the signature` (401) | `USERTRACK_SECRET` / `USERTRACK_PROJECT_ID` differ from the integration | Fix the env vars in every environment, redeploy, or rotate the secret |
| `rejected the request as stale` | Server clock off by > 5 minutes | Fix NTP on the host |
| `could not count users` (500) | Your count source threw | `debug: true` logs the error server-side (never sent to UserTrack) |
| Counts labelled *approximate* | A source returned `exact: false` (Convex cap) | Keep an exact counter (aggregate component) |
