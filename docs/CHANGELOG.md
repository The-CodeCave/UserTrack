# Changelog

## 0.4.0 — Growth data layer (2026-09-02)
- Provider layer v3 (`convex/providers/types.ts`): per-configuration **capability model** (`describe()` → `totalUsers` · `createdUsers` · `historicalUsers` · `activationEvents` · `retention` · `traffic` · `revenue`), **source verification levels** (`verified` / `partially_verified` / `self_reported` via `verificationLevel()`), `runtime()` + `toPostgres()` for TCP sources, `fetchJson` backoff on 429/503 (Retry-After, ≤5 s, ≤2 retries), `mapLimit` for bounded backfills. `convex/providerRun.ts` is the only V8-vs-Node switch; nothing else branches on provider kind. Docs: `docs/PROVIDERS.md`.
- **PostgreSQL provider** (`convex/providers/postgres.ts` + `convex/node/postgres.ts`, `"use node"`, `pg` as external package): read-only session (`SET default_transaction_read_only = on`), 10 s connect / 20 s statement timeouts, aggregate SQL only (`count(*)` with optional created-at / soft-delete / status filters, `GROUP BY day` history), identifiers validated + quoted, epoch columns supported, custom `$1` SELECT for activation (validated: single SELECT/WITH, no `;`, no write keywords), secret-free error mapping (`explain()`), verified trust. Setup wizard (`postgres-wizard.tsx`): connect + SSL → ranked table list (≤200, row estimates) → column suggestions + preview count → live test → connect; SQL template for a `usertrack_ro` role in the UI and in MCP setup instructions.
- **Supabase read-only database mode** (`mode: "database"`, session-pooler hosts only): `auth.users` with `created_at` / `deleted_at` → verified 24h/7d/30d signups + 30-day history in one query; API mode (service role key) kept as fallback. Mode is derived from the config (connection string present → database). Runs through the same Node runtime.
- **Firebase signup scan**: `accounts:batchGet` pages of 1,000 keeping only `createdAt` (≤ `FIREBASE_SCAN_LIMIT` = 100k accounts) → real 24h/7d/30d windows + 30-day history; larger projects fall back to totals + snapshot deltas; `scanSignups: false` opt-out. **Clerk**: 4 concurrent history requests, 429 backoff. Recommendation order `supabase → clerk → firebase → auth0 → postgres → endpoint` with new detection aliases (`DATABASE_URL`, `pg`, `prisma:postgresql`, `drizzle-pg`, Neon, Vercel Postgres, …).
- Live **"Test connection"** card (`integrations.test`): validates, fetches once, shows detected counts, source verification level, masked config and the capability list before anything is stored. Connected sources show verification + capabilities on the manage page.
- **Activation + funnel v2** (`convex/domain/funnel.ts`): Visitors → Signups → Activated → Paying over `7d` / `30d` / `90d` from stored `dailyMetrics` rows (never snapshots), previous window of the same length, per-stage `changePct` / `conversionPct` / `previousConversionPct`, flow vs stock stages, fallbacks to materialized metrics while history is short, **per-stage provenance** (`source { provider, label, verification }`) and a funnel-level `verification` (`verified` only when every stage is). Owner view includes private traffic/revenue; public view only opted-in stages. Onboarding gained an optional activation step. Docs: `docs/METRICS.md`.
- **Trending Score v2** (`convex/lib/trending.ts`): `100 · volume · growth · acceleration · trust · activation · freshness · history`; `freshness` = 1 up to 24 h since the last sync, linear to 0.5 at 72 h, 0 after; `history` = `0.6 + 0.4 · min(1, trackedDays/14)`; no signal (score 0) below 5 new users, for stale sources or under review. Per-window ranks `trendingRank24h` / `trendingRank` (7d) / `trendingRank30d` with `prev*` = position at the previous rerank; deterministic order (`score → newUsers30d → totalUsers → slug`). `public.trendingExplain` + ⓘ tooltip and one-line `explain` on trending cards. Docs: `docs/TRENDING.md`.
- **Discovery feed from stored events** (`public.feed`, `feedItems`): milestones + `spike` / `activation_spike` / `launched` / `verified` events merged and deduplicated by stable ids (`milestone:{saasId}:{key}`, `{kind}:{saasId}:{day}`); `launched` written once at first publish (`saas.launchedAt`), `verified` once at the first verified users sync (`saas.verifiedAt`); `events.by_time` index. `/discover` v2: Trending now, Fastest today / this week, New & rising, Recently verified, Biggest movers (7-day trending rank gains), Hidden gems with public rules (`< 1,000` users, ≥ 10 new / ≥ 10 % in 7d, ≥ 7 days history, trust ≥ 60), Top developer tools, Top AI, category counts, activity feed.
- **Share engine v2** (`src/lib/share.ts`, `src/lib/og/share-card.tsx`): card kinds `users` · `growth` (30d) · `week` (7d) · `rank` · `trending` · `activation` · `milestone-<id>` · `spike-<id>`; `/s/[slug]/share/[kind]` page, `opengraph-image` and `/card` PNG (1200×630, `?size=square` → 1080×1080) from one renderer; `Cache-Control: public, max-age=300, s-maxage=3600, stale-while-revalidate=86400`; growth spikes get their own share card.
- **Badges / embeds v2** (`src/lib/badge.ts`, `/api/badge/[slug].svg`): types `users` · `growth` · `trending` · `verified` · **`chart`** (320×120 live widget: total, window delta, 30-day sparkline), `theme=dark|light`, `window=7d|30d` (growth, chart), `compact=1` (drops the word, keeps the mark; chart 320×96); 120 req/min per IP burst limit (429 + `Retry-After`), CORS `*`, `nosniff`, edge cache 1 h, neutral "not found" SVG with 404 for drafts/unknown slugs. New configurator page `/app/saas/[id]/embed` (type, timeframe, theme, size, live preview, HTML / Markdown / image URL).
- **Benchmarks v2** (`convex/lib/benchmarks.ts`, `daily.benchmarks`): cohorts `all` / `cat:<slug>` / `size:<bucket>` over rankable products, five metrics (`growth30dPct`, `newUsers30d`, `activationRatePct`, `growth7dPct`, `trendingScore7d`), `MIN_SAMPLE = 5` (smaller cohorts are deleted), deciles only, percentile rounded to steps of 5 in `5 … 95`, `medianMultiple`, insight sentences, public statement only for the top quarter (`public.benchmarkHighlight`, category → size → all) shown on the product page. Docs: `docs/BENCHMARKS.md`.
- **Compare v2**: `/compare?s=a,b,c,d&days=7|30|90|365|all` (default 30) reading daily rows only, chart modes Total / Indexed (= 100 at each product's first day in the window), window-growth row, share buttons, OG image route `/compare/og?s=…&days=…` (1200×630, cached 1 h).
- **Public API v1** additions: `GET /saas/{slug}/funnel?timeframe=`, `GET /saas/{slug}/benchmarks`, `GET /discover?category=&limit=` (sections + deduplicated feed), `GET /compare?s=&days=` (absolute + indexed series); new DTOs, OpenAPI updated. Docs: `docs/API.md`.
- **MCP**: 8 new tools (23 total) — `usertrack_get_provider_recommendation`, `usertrack_get_activation_setup`, `usertrack_get_funnel`, `usertrack_get_trending`, `usertrack_get_benchmark`, `usertrack_compare_projects`, `usertrack_get_share_card`, `usertrack_get_embed_code`; setup workflow is now 10 steps (provider recommendation with the Supabase → Clerk → Firebase → PostgreSQL → endpoint priority, optional activation step); `postgres` accepted by the integration tools. Docs: `docs/MCP.md`.
- Onboarding + dashboard IA: manual onboarding has 5 steps (Profile → Your SaaS → Data source → Activation (optional, skippable) → Publish) with a richer publish preview; overview page shows state-derived "Next actions" (publish, connect activation, add badge, share card, see how you compare) and compact benchmark cards; manage page sections with anchors (`#overview` `#growth` `#funnel` `#benchmarks` `#integrations` `#sharing` `#embeds` `#settings`) and a "Next steps" row.
- Tests: 262 (28 files) — adds funnel, discovery/feed (`convex-test`), Postgres SQL builders + error mapping, Clerk backoff, Firebase pagination + scan cap, benchmarks, share copy/kinds, badge v2, new DTOs, MCP tool registry.

## 0.3.0 — Public API keys & MCP (2026-09-02)
- Tagline: "the growth data layer for SaaS" — website, public API and MCP share one domain layer.
- Domain layer `convex/domain/{projects,integrations,metrics}.ts` with typed `DomainError`; `saas.ts` / `integrations.ts` and the new gateway delegate to it. Domain normalization (`convex/lib/domain.ts`) makes project creation idempotent by canonical domain.
- Developer tokens (`developerTokens`): API keys `ut_api_…` and MCP tokens `ut_mcp_…`, SHA-256 hashed, shown once, six scopes, optional expiry (≤365 d), revoke, max 25 active; per-day usage buckets (`apiUsage`); audit trail (`auditLogs`). `/app/developer` page with key/token creation, usage and activity.
- Token-authenticated Convex gateway (`convex/gateway.ts`): `UT_GATEWAY_SECRET` check, scopes, strict ownership by id or slug, daily quota, create ≤10/h, verify 20 s cooldown, sync 60 s cooldown, audit on every write, secrets never returned.
- Public API: optional API keys via `Authorization: Bearer` or `X-API-Key` (1,000 req/day + 120/min burst, uncached), `X-RateLimit-Window` and `X-RateLimit-Reset` headers, new endpoints `GET /saas/{slug}/metrics`, `GET /trending`, `GET /users/{username}`, error codes `unauthorized` / `revoked` / `expired` / `forbidden`, OpenAPI 3.1 document at `/api/openapi.json`.
- MCP server at `/mcp` (Streamable HTTP, stateless, JSON responses, `@modelcontextprotocol/sdk`): 15 tools (account, projects, create/update project, supported integrations, setup instructions, configure/verify/sync integration, metrics, history, rank, milestones, share URLs), server instructions with the 9-step setup workflow, prompt `add_project_to_usertrack`, structured `isError` results with hints, per-token burst + daily limits, discovery document on `GET /mcp`.
- Integration catalog and executable setup instructions (`convex/lib/integrationSetup.ts`): 10 providers with roles, trust, detection aliases, credential locations and env var hints, least-privilege permissions, security rules, endpoint code templates per framework/ORM, recommendation from detected stack.
- Onboarding "Set up with AI in 60 seconds": MCP token (7-day expiry), config snippets for Claude Code / Cursor / Codex CLI / VS Code / generic, agent prompt, live status derived from the audit trail (`convex/onboarding.ts`), funnel events; manual setup still available.
- `/developers` rewritten: overview, quickstart, API reference with examples/errors/limits, MCP reference (scopes, tools, workflow, limits, security, troubleshooting), examples. New `docs/MCP.md`; `docs/API.md`, `docs/ARCHITECTURE.md`, `docs/ASSUMPTIONS.md`, `docs/ROADMAP.md`, `README.md` updated.
- Tests: token format/hashing/scopes, domain normalization, integration setup.

## 0.3.0 — Email system (2026-09-02)
- Resend mailer behind one entry point (`convex/email/send.ts`): dedupe ledger (`emailEvents`), preference + suppression checks, retries with backoff, Resend idempotency keys, `List-Unsubscribe` one-click headers, delivery log with provider message ids.
- Typed, table-based HTML templates in the blueprint brand (dark graphite, white linework, pink accent), plain-text twins, XSS-safe escaping; every template unit-tested.
- Better Auth: welcome email (doubles as email verification for email+password signups, plain for Google), verification re-send from settings, password reset flow (`/forgot-password`, `/reset-password`).
- Lifecycle: profile unfinished after 24h, product without source after 24h (per-entity scheduled functions, once each), first-sync confirmation, source stopped syncing (6 consecutive failures or ≥3 with 24h silence, once per episode), source recovered.
- Growth: user milestones (10 → 1M, highest crossing mails, lower ones recorded), ranking milestones (Top 100/50/25/10/5/#1, board-size aware), spike alerts (≥2.5× the 30-day daily baseline, ≥20 users, 14-day history, 7-day cooldown), 7 quiet days (once per quiet period, healthy sources only), followed-product updates (opt-in, major events only).
- Monthly growth report: one consolidated email per founder for the completed calendar month (per project: start/end users, new, net, %, activation, rank start → end from daily rank history, biggest day, milestones; overall summary), generated on the 1st in pages of 50, delivered at 09:00 local time; in-app at `/app/reports`.
- Weekly digest rewired to the mailer and preferences (opt-in by default; silent when there is nothing to report).
- Preferences: `emailPreferences` per Better Auth user (product nudges, user / ranking milestones, growth alerts, monthly report, weekly digest, followed updates, timezone), `/app/settings/notifications`, signed 90-day preference links (`/email/preferences?token=…`), one-click unsubscribe endpoint, transactional mail never gated.
- Resend webhook (`/webhooks/resend`, Svix signature verified): delivered / bounced / complained / failed → event status; hard bounces and complaints suppress non-essential mail (`emailRecipients`).
- Google sign-in button + provider config (needs OAuth client, see `HUMAN_TODO.md`).
- Tests: 115 (rules, templates, tokens, webhook signatures, Resend adapter, and `convex-test` function tests for dedupe, preferences, lifecycle state machine, milestones, spikes, followers, monthly reports, webhook, token access).

- Blueprint design system: graphite surfaces, white linework, pink `#FB0184` accent, Geist Sans/Mono, corner-tick panels, grid backgrounds.
